### Fixed
- `scripts/validate_research_run_state.py` (#434): the delivered gate no longer trusts a self-consistent audit JSON. The report contract now goes through the canonical `validate_contract()` boundary in strict mode (single top-level ` ```contract ` block; canonical primary/secondary routes; no primary-as-secondary, duplicate secondaries, or unknown routes; stable artifact identity blocking) before any expected audit id is derived, so a forged `<route>-secondary-hard-fail` for an undeclared route can no longer satisfy delivered. Contract errors fail closed while pure advisory warnings (e.g. more than two secondary routes) stay non-blocking, so a strict producer `conditional-pass` is not rejected here. The same boundary requires exactly one visible route-status block with exactly one route declaration; `count_report_route_blocks()` and `extract_report_route_declaration()` now share one line-anchored H2/H3 + English/中文 heading matcher, so producer-accepted headings (`## 附录：路由与审计状态`, nested `### Route and audit status`) stay deliverable while deleting, changing, duplicating, or unresolvably renaming the declaration fails closed. The Pack `## Primary route` / `## Artifact id` are re-read via the producer parsers — duplicate Pack declaration sections, missing `## Artifact id`, and unresolvable routes fail closed, and Pack/contract/audit routes must agree with no raw-string fallback. The Pack `## Activation snapshot` is re-parsed and must match the contract snapshot and the Run State `activation_reference`. Unknown routes and registry/parse failures return structured delivered errors (exit code 2 with a JSON payload) instead of an unhandled `UnknownRouteError` traceback; report/Pack evidence locators are re-resolved against the canonical visible body, so phantom or fenced/HTML-hidden `report-section` / `report-table` / `pack-section` / `pack-table` evidence no longer passes on JSON self-attestation. `validate_contract.extract_report_route_declaration()` gains a backwards-compatible `unknown_route_is_error` flag for consumers that own the whole cross-artifact boundary, and duplicate secondary routes are now errors under strict / warnings in legacy non-strict mode. Run State identity is bound across the chain: `artifact_id` must equal the canonical contract/Pack artifact id on the direct and `--from/--to` delivered paths, and the contract `activation_snapshot` is compared with the Run State `activation_reference` unconditionally (the Pack `## Activation snapshot`, when present, must match both). The Pack is parsed once from the single read through the public `PackDeclarations` API (`validate_pack_sections_text` / `resolve_pack_primary_route_text` / `extract_pack_artifact_id_text`), so one delivered validation cannot mix Pack versions and no private helper needs to be imported across modules. Error handling is total: unhashable malformed `secondary_routes` entries no longer raise `TypeError`, `RegistryError` (not only `UnknownRouteError`) is converted to structured errors at every registry boundary including the `run_forward_evals` import, invalid-UTF-8 audit/run-state files return structured read errors, and the CLI delivered wrapper has a last-resort fail-closed guard. Delivered now requires a valid report contract `activation_snapshot` (validated via `validate_activation_reference`) and compares it with the Run State `activation_reference`, so deleting the contract snapshot can no longer unbind the activation identity. Pack declaration parsing is strictly H2 line-anchored through one shared `_pack_h2_section_body()` (`## Primary route` / `## Artifact id`, required exactly once via `require_exactly_one`), so `### Primary route` / `### Artifact id` or an inline prose heading mention cannot masquerade as a required declaration; the cardinality counter and the section extractor now consume one shared `_pack_h2_heading_pattern()` (`[ \t]`, never `\s`, so a `##` followed by a newline cannot count). Activation reference version semantics are closed in the canonical validator: a contract `activation_snapshot` must use the supported `SNAPSHOT_VERSION` and the canonical decision-tree version, and the contract's top-level `decision_tree_version` must agree with the nested reference even when no full activation snapshot artifact is supplied. Malformed-input totality now covers the audit fields too: a non-string `execution_source` is reported before any set-membership test, the shared-workflow audit-id check consumes the already type-filtered id list, and `boundary_judgment.checked_conditions` entries must be non-empty strings (`minItems: 1` / `minLength: 1` added to the JSON schema) — plain JSON type combinations can no longer raise `TypeError` out of the canonical validator (direct callers included), instead of relying on the CLI's last-resort guard. The report route-status matcher now shares the strict `[ \t]` heading grammar with the Pack parser, so a cross-line `##\nRoute and audit status` cannot inflate block cardinality. `--chain` reads the Pack once and threads the same snapshot through run-state resolution, status mapping and the delivered consumer (which also accepts a pre-read `pack_text`), and the `audit_report` producer now consumes the same public `parse_pack_declarations()` result instead of separate path wrappers.

### Changed
- `references/parallel-research.md` now includes a **Batch parallelism (rate-limit safe)** section with a max-2-concurrent rule to prevent MiniMax API 429 errors during parallel track execution.

### Why
- During a real deep-research session, running 3-4 parallel sub-agent tracks simultaneously caused multiple concurrent `web_search` calls that exceeded MiniMax's search API concurrency limit, resulting in 429 errors and track failures.
- The fix uses batch parallelism: at most 2 tracks run concurrently; remaining tracks wait for the current batch to finish before spawning. This keeps total research time near-optimal (~2× single-track) without hitting rate limits.
- 4 tracks → two batches (2+2); 3 tracks → two batches (2+1); 1 track → direct run.

### Process
- Fix was identified from a real production failure during a live Minimax research session.
